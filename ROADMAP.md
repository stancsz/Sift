# Roadmap to adoption and release

Sift deterministically filters repeated agent history. Current evidence shows a real reduction in provider prompt tokens with a measurable quality cost on an exposed LongBench cohort. It does not yet show reliable held-out agent-task outcomes, user adoption, or broad client compatibility. Sift remains a preview; do not market the current evidence as parity or general quality improvement.

## Available now

The tested GitHub `v0.10.0` pre-release is a Python library and LiteLLM Proxy callback. The unreleased `0.11.0.dev0` main branch adds a LiteLLM-free `sift serve` CLI for Ollama and OpenAI Chat Completions-compatible base URLs. Its explicit `byte-estimate` tokenizer measures UTF-8 request size; it is not a provider tokenizer and cannot guarantee upstream context fit. The site and README provide a deterministic no-inference demo with a local stub, which verifies request compaction and forwarding only.

## Current state by goal

- **Local tests and low-cost CI — implemented:** the PR #22 candidate (same source content as main `6fcec84`) passed **393 tests** locally on Python 3.13.11 in 113.25 seconds with 18 dependency warnings. The PR's Python 3.12 core smoke passed in 46 seconds; its full matrix was skipped by design. The full multiversion suite and offline comparison run weekly or manually. See [evaluation](docs/evaluation.md).
- **Clear user value — improved, awaiting user validation:** the homepage now leads with “Long agent history. Less context to send.” It pairs measured prompt-token reduction with the negative task-majority result and exposes the caveats above the fold. Sol's final image review and independent mobile QA passed the 1280×800 and 390×844 renders. Live Pages is deployed from `76f3baf` at <https://stancsz.github.io/sift/>. No external user has tested or confirmed the value yet.
- **GitHub Pages — live:** the page includes the deterministic compaction interaction, mechanism, evidence, limitations, standalone quick start, and project links. PR #19 moved the strongest verified trade-off into the first screen. Check site links and responsive behavior when a material page change ships; Pages deployment run `39425862451` succeeded for `76f3baf`.
- **LongBench evidence — expanded, quality concern remains:** the completed three-repeat 344-question run produced 2,063 valid receipts from 2,064 scheduled requests; one Full HTTP 529 lacked a receipt and was not retried. The 343 paired task-majority counts were Full 145/343 and Sift 127/343 (−5.25 pp; cluster-bootstrap 95% CI −10.20 to −0.29 pp). Across all receipts Sift used 59.66% fewer prompt tokens and had 58.72% lower cache-sensitive BYOK receipt cost. Questions and labels were exposed during development; this is not held-out or agent-loop quality evidence. Do not combine samples. Use a separately authored blinded agent-task set for generalization. AppWorld remains parked until a complete test-free route and an independently controlled evaluator/operator boundary are demonstrated.
- **Standalone CLI — implemented, initial compatibility verified:** `sift serve` needs no LiteLLM and accepts Ollama or another OpenAI Chat Completions-compatible base URL. The OpenAI Python SDK→Sift→Ollama tool round-trip and LiteLLM Python client→Sift→loopback fixture compaction smoke cover two named clients; PR #22's Python 3.12 smoke passed. The LiteLLM fixture makes no model call. More endpoint/provider combinations and failure-mode coverage remain open; do not generalize from these two paths.
- **Adoption — unverified:** the protocol permits up to three inference-free sessions with volunteers. Issue [#13](https://github.com/stancsz/sift/issues/13) is open with zero replies and no sessions; it points to the current homepage and its exact task now matches the README, including the public-comment disclosure. Do not contact people directly or treat clicks/task completion as adoption.
- **Stable release — not ready:** the latest GitHub release is the v0.10.0 pre-release; the public PyPI endpoint returns 404 and pending-publisher setup remains unverified. The manual Trusted Publishing workflow only runs from `main`, whose PyPI environment allowlist is configured. The required reviewer can self-approve, admins can bypass, `v*` tags have an owner bypass, and `main` has no branch-protection rule. See the [release-control audit](docs/evals/release-control-audit-2026-10-20.md). Resolve the independent-gate and owner-side PyPI checks, then run a non-publishing rehearsal. Stable publish still requires held-out task evidence, compatibility coverage, an honest adoption disposition, and full release checks.

## Ordered next work

1. **First-run evidence:** the README, protocol and issue #13 have matching task instructions and public-comment privacy boundaries. Issue #13 currently has no replies and no sessions have run. If volunteers opt in, run no more than three sessions using the deterministic local fixture. Otherwise record that value remains unvalidated; do not contact people directly.
2. **Held-out quality:** preserve the LongBench negative result and do not tune on the exposed set. The generated-data Docker output boundary passed independent review locally and on an ephemeral hosted runner, but no real holdout source or separate evaluator/reviewer permissions are cleared. Freeze independently authored multi-turn task prompts, hidden answers, a stable harness and an independent accepted-outcome rubric; verify a test-free route and complete quarantine boundary before opening any holdout. AppWorld remains parked; synthetic nonproprietary tasks remain the fallback. The prior $100 cap was scoped to the completed study; obtain new authorization before paid inference.
3. **Compatibility:** two named Python clients now have deterministic coverage. Expand only when a concrete supported endpoint/provider gap blocks the declared contract; add failure-path coverage without broadening the OpenAI Chat Completions API promise silently.
4. **Release controls:** the latest audit still finds owner self-approval/admin bypass for `pypi`, an owner bypass on protected `v*` tags, no `main` branch-protection rule, and unverified PyPI pending-publisher setup. Verify the authenticated PyPI configuration; decide whether to change or explicitly accept those controls; run the guarded build/release rehearsal without publishing.
5. **Stable release:** reconcile the quality and adoption disposition, run full release checks on a clean stable tag, publish the package with Trusted Publishing, verify installation from PyPI, then publish reviewed GitHub release notes. Do not call the current `v0.10.0` pre-release stable.

The 2026-10-20 first-run council and post-LongBench council are preserved in the goal/handoff. The first-run council prioritized usability before additional client integrations; the post-result council recommended a blind paired multi-turn agent-task benchmark before algorithm changes and retaining the negative exposed-LongBench result. The #20 first-run path and #22 two-client smoke are complete; volunteer feedback and blind accepted-task quality remain unresolved. These are accountable decisions informed by attributed reviews, not votes.
