# Roadmap to adoption

Sift reduces repeated agent history with deterministic, extractive compaction. Its current limits matter: selected LongBench runs show a quality trade-off, and no held-out study yet proves reliable task completion, lower total cost, or faster work in real coding agents.

## Available now

The tested `v0.10.0` release is a Python library and LiteLLM Proxy callback. The unreleased `0.11.0.dev0` source also adds a LiteLLM-free `sift` command for OpenAI Chat Completions clients, including Ollama and other compatible base URLs. Its explicit `byte-estimate` mode measures UTF-8 request size; it is not a provider tokenizer and cannot guarantee context fit.

## Current adoption work

- **Reliable local checks:** the current readiness worktree passed **380 tests on Python 3.14 in 105.86 seconds** with 17 dependency warnings, using `.venv-local-qa` after installing `.[litellm,test]`. The focused known-unknown-reserve tests are included. PR #7's [Python 3.12 Core smoke](https://github.com/stancsz/sift/actions/runs/39272382994) passed in 29 seconds. The four-version full matrix remains weekly/manual to keep ordinary PR CI short. An isolated Ubuntu/Python 3.12 suite previously passed 370 tests; the offline authored comparison returned 100/100 Sift hits and 0/100 head/tail hits.
- **Clear first use:** the README and site show a long-history deployment-setting retrieval example plus Ollama/other OpenAI-compatible base-URL setup without LiteLLM. The unreleased CLI installs directly from GitHub `main` without a manual checkout; a clean Windows virtual environment confirmed `sift serve` works with LiteLLM absent. The bundled demo still requires a checkout and verifies request compaction plus retrieval of its synthetic buried setting, not general answer quality. Desktop and mobile site sections received independent READY reviews. The actual homepage was independently judged READY for a 20-second comprehension session at 1280×800; up to three inference-free local-Ollama sessions are owner-authorized, and the opt-in [issue #13](https://github.com/stancsz/sift/issues/13) had no respondents at last check.
- **Public site:** GitHub Pages is live at <https://stancsz.github.io/sift/>. PR #7 added an offline Full / With Sift interaction that uses a captured result from the real compactor; Pages deployed main commit `8ce6dd2` successfully, and the published URL returned HTTP 200. The GitHub repository homepage points to Pages.
- **Broader quality evidence:** the public LongBench v2 record covers the 100-question/three-repeat study, an incomplete one-repeat run with 446 matched rows from 503 exposed questions, a four-task field-pruning pilot that remains behind Full context/off by default, and the latest interrupted 344-question cohort. The latest run stopped at 542/2,064 after an HTTP 529 without usage receipt; 90 task clusters are currently complete in both arms. Its partial observed exact-choice scores are 110/270 Full and 122/270 Sift, with an approximate task-cluster interval spanning −3.26 to +12.15 points. These exposed-development data do not establish parity, non-inferiority, or agent-task quality. The five unresolved request outcomes now require exact private reports and a combined $0.786816 worst-case reserve before any further dispatch. The user authorized up to $100 in aggregate; refresh route/pricing and account state, include old exposure, never retry the 529, and remain within that cap. AppWorld `test_challenge` remains parked until its output quarantine can be rehearsed without test access. See the [evaluation record](docs/evaluation.md) and [source review and protocol](docs/evals/agent-holdout-source-review-2026-10-18.md).
- **Adoption evidence:** the Advisor council recommended up to three inference-free first-run sessions with developers who already use long-context workflows. The [session protocol](docs/evals/first-run-usability-protocol-2026-10-18.md) is independently reviewed; the homepage preview at 1280×800 was also independently cleared for comprehension testing. Recruitment is owner-authorized through the opt-in [issue #13](https://github.com/stancsz/sift/issues/13); no external participants have been contacted directly, and there were no respondents at last check. Record comprehension, setup time, blockers, relevance, and voluntary follow-through. Walkthrough completion is not adoption.
- **Compatibility:** automated checks cover non-streaming/SSE, incremental streaming, active tool-call/result turns, Bearer-key forwarding, upstream errors, and Ollama reasoning metadata. A local OpenAI Python SDK 2.54.0 → Sift → Ollama two-request tool round-trip passed on `qwen3.5:4b`, preserving `build-1842` while compacting both requests. This verifies that local loopback path, not other named clients or remote providers; check broader compatibility before a stable release.
- **Release:** `0.11.0.dev0` is installable from GitHub but is not a stable release or PyPI package. The standalone CLI smoke confirms the base install does not pull in LiteLLM; the base URL must still be an OpenAI Chat Completions-compatible endpoint, and `byte-estimate` cannot guarantee the provider's token count or context fit. A manual tag-based Trusted Publishing workflow and operator steps are prepared in [the release guide](docs/releasing.md); it verifies the selected stable tag, full suite, and offline comparison, builds and checks wheel/sdist, and smoke-tests both without LiteLLM before publishing. The public `sift-context` PyPI endpoint currently returns 404; owner-side pending-publisher configuration must be confirmed before first upload. Resolve the compatibility, evaluation, and adoption gates before a stable release.

## Evidence today

The [evaluation record](docs/evaluation.md) summarizes the completed 600-response LongBench v2 study, a broader but incomplete 503-question matched run, a four-task field-pruning pilot, and task-specific native-agent checks. All LongBench questions were exposed during development. The results are not blind validation, accepted-task quality, or proof of parity. Keep claims scoped to those datasets, denominators, and limitations.
