# Roadmap to adoption and release

Sift deterministically filters repeated agent history. Current evidence shows a real reduction in provider prompt tokens with a measurable quality cost on an exposed LongBench cohort. It does not yet show reliable held-out agent-task outcomes, user adoption, or broad client compatibility. Sift remains a preview; do not market the current evidence as parity or general quality improvement.

## Available now

The tested GitHub `v0.10.0` pre-release is a Python library and LiteLLM Proxy callback. The unreleased `0.11.0.dev0` main branch adds a LiteLLM-free `sift serve` CLI for Ollama and OpenAI Chat Completions-compatible base URLs. Its explicit `byte-estimate` tokenizer measures UTF-8 request size; it is not a provider tokenizer and cannot guarantee upstream context fit. The site and README provide a deterministic no-inference demo with a local stub, which verifies request compaction and forwarding only.

## Current state by goal

- **Local tests and low-cost CI — implemented:** the current main suite passes **392 tests** on Python 3.13.11 in 137.89 seconds with 17 dependency warnings. Pull requests run a Python 3.12 core/CLI/demo smoke; the four-version full suite and offline comparison run weekly or manually. PR #19 smoke passed in 46 seconds and its post-merge main smoke in 48 seconds. See [evaluation](docs/evaluation.md).
- **Clear user value — improved, awaiting user validation:** the homepage now leads with “Long agent history. Less context to send.” It pairs measured prompt-token reduction with the negative task-majority result and exposes the caveats above the fold. Sol's final image review and independent mobile QA passed the 1280×800 and 390×844 renders. Live Pages is deployed from `76f3baf` at <https://stancsz.github.io/sift/>. No external user has tested or confirmed the value yet.
- **GitHub Pages — live:** the page includes the deterministic compaction interaction, mechanism, evidence, limitations, standalone quick start, and project links. PR #19 moved the strongest verified trade-off into the first screen. Check site links and responsive behavior when a material page change ships; Pages deployment run `39425862451` succeeded for `76f3baf`.
- **LongBench evidence — expanded, quality concern remains:** the completed three-repeat 344-question run produced 2,063 valid receipts from 2,064 scheduled requests; one Full HTTP 529 lacked a receipt and was not retried. The 343 paired task-majority counts were Full 145/343 and Sift 127/343 (−5.25 pp; cluster-bootstrap 95% CI −10.20 to −0.29 pp). Across all receipts Sift used 59.66% fewer prompt tokens and had 58.72% lower cache-sensitive BYOK receipt cost. Questions and labels were exposed during development; this is not held-out or agent-loop quality evidence. Do not combine samples. Use a separately authored blinded agent-task set for generalization. AppWorld remains parked until a test-free aggregate-output quarantine rehearsal passes.
- **Standalone CLI — implemented, compatibility gate open:** `sift serve` needs no LiteLLM and accepts Ollama or another OpenAI Chat Completions-compatible base URL. CI builds and smoke-tests the wheel without LiteLLM; the deterministic fixture covers a no-inference request path. One local OpenAI Python SDK→Sift→Ollama tool round-trip is documented, but a second independent named client and broader compatibility matrix remain to be verified.
- **Adoption — unverified:** the protocol permits up to three inference-free sessions with volunteers. Issue [#13](https://github.com/stancsz/sift/issues/13) is open with zero replies and no sessions; it already points to the current homepage and describes the fixture task. After this docs PR merges, sync its exact commands with the README and disclose that comments are public. Do not contact people directly or treat clicks/task completion as adoption.
- **Stable release — not ready:** `sift-context` is not on PyPI; the latest GitHub release is the v0.10.0 pre-release. The guarded manual Trusted Publishing workflow and release guide exist. Confirm the PyPI pending publisher, protected `pypi` environment/reviewer, `main` restriction and `v*` tag protections, then run a non-publishing rehearsal. Stable publish still requires held-out task evidence, compatibility coverage, an honest adoption disposition, and full release checks.

## Ordered next work

1. **First-run task and feedback path:** README and session protocol now state the checkout prerequisite, actual successful demo output, and privacy-safe feedback boundary. Refresh issue #13 to match those instructions and explicitly disclose that its comments are public. Observe up to three sessions only if volunteers opt in.
2. **Held-out quality:** freeze independently authored task prompts/answers and an accepted-outcome rubric; verify blinded scoring and aggregate-only outputs with a no-inference rehearsal. Reuse AppWorld only if the quarantined path is independently verified; otherwise use nonproprietary synthetic tasks. No additional paid inference is authorized by the previous study-specific cap.
3. **Compatibility:** demonstrate deterministic behavior for at least two named supported clients and failure cases without broadening the stated Chat Completions API contract.
4. **Release controls:** verify PyPI and GitHub environment/tag protections; exercise the guarded release build without publishing; resolve compatibility, quality, and adoption gates, then publish a stable version and reviewed release notes.

The 2026-10-20 Codex Advisor council ranked the next work differently: Gemini 4 Argon favored multi-client compatibility first, then recruitment and release-gate checks; GPT-6.1 Sol gave its own verdict and put usability first because no users have tried the flow. The current Northstar work sequence is to refresh the first-run task, then verify compatibility and release controls. This reconciles the differing advice; it is not a vote. See the [council record](docs/evals/sift-advisor-council-first-run-2026-10-20.md), which preserves an attributed session summary rather than a verbatim transcript.
