# Roadmap to adoption and release

Sift deterministically filters repeated agent history. Current evidence shows a real reduction in provider prompt tokens with a measurable quality cost on an exposed LongBench cohort. It does not yet show reliable held-out agent-task outcomes, user adoption, or broad client compatibility. Sift remains a preview; do not market the current evidence as parity or general quality improvement.

## Available now

The tested GitHub `v0.10.0` pre-release is a Python library and LiteLLM Proxy callback. The unreleased `0.11.0.dev0` main branch adds a LiteLLM-free `sift serve` CLI for Ollama and OpenAI Chat Completions-compatible base URLs. Its explicit `byte-estimate` tokenizer measures UTF-8 request size; it is not a provider tokenizer and cannot guarantee upstream context fit. The site and README provide a deterministic no-inference demo with a local stub, which verifies request compaction and forwarding only.

PRs #28–31 passed Core smoke in 43, 44, 48 and 48 seconds; post-merge main smoke passed in 51, 51, 48 and 43 seconds. Full multiversion suite and offline comparison remain weekly/manual. PR #32 merged the protected-main ancestry check as `05dc830`; its Core smoke passed in 44 seconds and post-merge main smoke in 49 seconds. See [evaluation](docs/evaluation.md).
- **Clear user value — improved, awaiting user validation:** the homepage now leads with “Long agent history. Less context to send.” It pairs measured prompt-token reduction with the negative task-majority result and exposes the caveats above the fold. Sol's final image review and independent mobile QA passed the 1280×800 and 390×844 renders. Live Pages is deployed from `76f3baf` at <https://stancsz.github.io/sift/>. No external user has tested or confirmed the value yet.
- **GitHub Pages — live:** the page includes the deterministic compaction interaction, mechanism, evidence, limitations, standalone quick start, and project links. PR #19 moved the strongest verified trade-off into the first screen. Check site links and responsive behavior when a material page change ships; Pages deployment run `39425862451` succeeded for `76f3baf`.
- **LongBench evidence — expanded, quality concern remains:** the completed three-repeat 344-question run produced 2,063 valid receipts from 2,064 scheduled requests; one Full HTTP 529 lacked a receipt and was not retried. The 343 paired task-majority counts were Full 145/343 and Sift 127/343 (−5.25 pp; cluster-bootstrap 95% CI −10.20 to −0.29 pp). Across all receipts Sift used 59.66% fewer prompt tokens and had 58.72% lower cache-sensitive BYOK receipt cost. Questions and labels were exposed during development; this is not held-out or agent-loop quality evidence. LongMemEval-V2 is a potential local matched memory-quality comparison with more agent-history relevance, but its questions/haystacks are public and its official submission validator requires Qwen3.5-9B/GPT-5.2 rather than MiniMax-M3. Do not present it as blind evidence or as a MiniMax leaderboard entry. AppWorld and GAIA remain uncleared for a blind paired holdout.
- **Standalone CLI — implemented, initial compatibility verified:** `sift serve` needs no LiteLLM and accepts Ollama or another OpenAI Chat Completions-compatible base URL. The OpenAI Python SDK→Sift→Ollama tool round-trip and LiteLLM Python client→Sift→loopback fixture compaction smoke cover two named clients; PR #22's Python 3.12 smoke passed. The LiteLLM fixture makes no model call. More endpoint/provider combinations and failure-mode coverage remain open; do not generalize from these two paths.
- **Adoption — unverified:** the user authorized up to three inference-free sessions with volunteers. Issue [#13](https://github.com/stancsz/sift/issues/13) is open with zero replies and no sessions; it points to the current homepage and its task matches the README, including the public-comment disclosure. No direct outreach has occurred. Do not treat clicks or task completion as adoption.
- **Stable release — not ready:** the latest GitHub release is the v0.10.0 pre-release; the public PyPI endpoint returns 404 and pending-publisher setup remains unverified. A temporary build of the current preview wheel and sdist passed strict metadata checks and a clean no-extras CLI smoke, but this does not replace the stable-tag workflow. The manual Trusted Publishing workflow only runs from `main`, whose PyPI environment allowlist is configured. `main` requires a PR and the short Core smoke, with zero approvals because `stancsz` is the sole collaborator; this is not independent human review. The check is loose (`strict=false`), and PyPI self-review/admin bypass plus `v*` tag-owner bypass remain. See the [release-control audit](docs/evals/release-control-audit-2026-10-20.md). Stable publish still requires held-out task evidence, compatibility coverage, an honest adoption disposition, verified PyPI publisher, and full release checks.

## Ordered next work

1. **First-run evidence:** the README, protocol and issue #13 have matching task instructions and public-comment privacy boundaries. The user authorized up to three inference-free sessions. Issue #13 currently has no replies and no sessions have run. If volunteers opt in, run no more than three sessions using the deterministic local fixture. Otherwise record that value remains unvalidated; do not contact people directly.
2. **Held-out quality:** preserve the LongBench negative result and do not tune on the exposed set. The generated-data Docker output boundary passed independent review locally and on an ephemeral hosted runner, but no real holdout source or separate evaluator/reviewer permissions are cleared. AppWorld has no documented split-scoped/test-free route; GAIA's public validation leaderboard is closed and its task-level score is final-answer-only. LongMemEval-V2 is a candidate for a local matched memory-system comparison: it reports accuracy and query latency over long web-agent histories, but exposes the benchmark data and per-question package outputs, offers no documented hidden evaluator set, and fixes Qwen3.5-9B/GPT-5.2 for its official leaderboard. It could support a clearly labeled public development reproduction with MiniMax-M3 if future authorization is obtained; it cannot currently supply blind holdout evidence or an official paired submission route. First build a no-inference synthetic adapter rehearsal; no real benchmark access or paid inference until a compliant protocol and fresh spend authorization exist.
3. **Compatibility:** two named Python clients now have deterministic coverage. Expand only when a concrete supported endpoint/provider gap blocks the declared contract; add failure-path coverage without broadening the OpenAI Chat Completions API promise silently.
4. **Release controls:** `main` now requires the short Core smoke on PRs and enforces the rule for admins, but the repo still has a sole self-approving `pypi` reviewer, admin bypass for the environment, an owner bypass for `v*` tags, and unverified PyPI pending-publisher setup. Verify the authenticated PyPI configuration; resolve or explicitly accept the remaining controls; run the guarded build/release rehearsal without publishing.
5. **Stable release:** reconcile the quality and adoption disposition, run full release checks on a clean stable tag, publish the package with Trusted Publishing, verify installation from PyPI, then publish reviewed GitHub release notes. Do not call the current `v0.10.0` pre-release stable.

The 2026-10-20 councils are preserved in the goal/handoff. They prioritized first-run usability, retaining the negative exposed-LongBench result, independent holdout evidence before selector changes, and most recently a release-path fix plus fixture compatibility work. LongMemEval-V2 is a public comparison candidate, not a blind holdout; see the source review. The #20 first-run path and #22 two-client smoke are complete; no volunteers have replied, and blind accepted-task quality remains unresolved. The user has authorized up to three inference-free sessions; no direct outreach has occurred. These are accountable decisions informed by attributed reviews, not votes.
