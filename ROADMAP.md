# Roadmap to adoption

Sift reduces repeated agent history with deterministic, extractive compaction. Its current limits matter: selected LongBench runs show a quality trade-off, and no held-out study yet proves reliable task completion, lower total cost, or faster work in real coding agents.

## Available now

The tested `v0.10.0` release is a Python library and LiteLLM Proxy callback. The unreleased `0.11.0.dev0` source also adds a LiteLLM-free `sift` command for OpenAI Chat Completions clients, including Ollama and other compatible base URLs. Its explicit `byte-estimate` mode measures UTF-8 request size; it is not a provider tokenizer and cannot guarantee context fit.

## Current adoption work

- **Reliable local checks:** the latest full local suite passed 372 tests on Python 3.14 in 98.20 seconds with 17 dependency warnings, including the OpenAI SDK loopback check and new Ollama reasoning-field regressions. PR #3's [Python 3.12 Core smoke](https://github.com/stancsz/sift/actions/runs/39267297872) passed in 32 seconds, and the main push run [#39267443322](https://github.com/stancsz/sift/actions/runs/39267443322) succeeded after merge. The four-version matrix remains weekly/manual to keep ordinary PR CI short. An isolated Ubuntu/Python 3.12 suite previously passed all 370 tests with 17 warnings; the offline authored comparison returned 100/100 Sift hits and 0/100 head-tail hits.
- **Clear first use:** the README and site show a long-history deployment-setting retrieval example plus Ollama/other OpenAI-compatible base-URL setup without LiteLLM. The demo verifies compaction and retrieves the buried setting; it demonstrates request behavior, not answer quality. Desktop and mobile site sections received independent READY reviews. First-run comprehension is still unmeasured; inference-free user sessions await owner authorization.
- **Public site:** GitHub Pages is live at <https://stancsz.github.io/sift/>. PR #2's accepted site changes were merged as `08d9f24`; the official Pages deployment succeeded and the published URL returned HTTP 200. The GitHub repository homepage now points to Pages.
- **Broader quality evidence:** the public LongBench v2 record now includes aggregate-only uncertainty for both the 100-question/three-repeat study and 446 matched rows from the incomplete 503-question run. All IDs are exposed development data, not a holdout. A prepared 344-pair/three-repeat cohort has a historical manifest reserve of $41.87, not a live quote or authorization; dispatch still requires prior-attempt/account reconciliation, a fresh route and price check, verified available funds, and a sufficient explicit user cap. AppWorld `test_challenge` remains an aggregate-only candidate; its runner must be rehearsed to suppress or quarantine task-level reports before test access. See the [evaluation record](docs/evaluation.md) and [source review and protocol](docs/evals/agent-holdout-source-review-2026-10-18.md).
- **Adoption evidence:** the Advisor council recommended three inference-free first-run sessions with developers who already use long-context workflows. The [session protocol](docs/evals/first-run-usability-protocol-2026-10-18.md) is independently reviewed and ready as a gated plan. No external participants have been contacted; sessions still need owner-authorized recruitment and a reviewed rendered preview. Record comprehension, setup time, blockers, relevance, and voluntary follow-through. Walkthrough completion is not adoption.
- **Compatibility:** automated checks cover non-streaming/SSE, incremental streaming, active tool-call/result turns, Bearer-key forwarding, upstream errors, and Ollama reasoning metadata. A local OpenAI Python SDK 2.54.0 → Sift → Ollama two-request tool round-trip passed on `qwen3.5:4b`, preserving `build-1842` while compacting both requests. This verifies that local loopback path, not other named clients or remote providers; check broader compatibility before a stable release.
- **Release:** the workflow and current Pages deployment have passed on GitHub, but neither proves the standalone `0.11.0` candidate is ready. Resolve visual, compatibility, evaluation and adoption gates before packaging or publishing it to PyPI.

## Evidence today

The [evaluation record](docs/evaluation.md) summarizes the completed 600-response LongBench v2 study, a broader but incomplete matched checkpoint, and task-specific native-agent checks. All LongBench questions were exposed during development. The results are not blind validation, accepted-task quality, or proof of parity. Keep claims scoped to those datasets, denominators, and limitations.
