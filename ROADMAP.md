# Roadmap to adoption

Sift reduces repeated agent history with deterministic, extractive compaction. Its current limits matter: selected LongBench runs show a quality trade-off, and no held-out study yet proves reliable task completion, lower total cost, or faster work in real coding agents.

## Available now

The tested `v0.10.0` release is a Python library and LiteLLM Proxy callback. The unreleased `0.11.0.dev0` source also adds a LiteLLM-free `sift` command for OpenAI Chat Completions clients, including Ollama and other compatible base URLs. Its explicit `byte-estimate` mode measures UTF-8 request size; it is not a provider tokenizer and cannot guarantee context fit.

## Current adoption work

- **Reliable local checks:** the current readiness worktree passed **388 tests on Python 3.14 in 110.62 seconds** with 17 dependency warnings, using `.venv-local-qa` after installing `.[litellm,test]`. The focused unknown-outcome, single-use continuation, and split-report analyzer tests are included. PR #17's Python 3.12 core smoke passed in 42 seconds; its full-suite CI job was skipped by the low-cost PR CI design. The four-version full matrix remains weekly/manual to keep ordinary PR CI short. An isolated Ubuntu/Python 3.12 suite previously passed 370 tests; the offline authored comparison returned 100/100 Sift hits and 0/100 head/tail hits.
- **Clear first use:** the README and site show a long-history deployment-setting retrieval example plus Ollama/other OpenAI-compatible base-URL setup without LiteLLM. The unreleased CLI installs directly from GitHub `main` without a manual checkout; a clean Windows virtual environment confirmed `sift serve` works with LiteLLM absent. The bundled demo still requires a checkout and verifies request compaction plus retrieval of its synthetic buried setting, not general answer quality. The live homepage was visually inspected at the available desktop viewport, but an independent review at the required 1280×800 viewport is not established. Keep first-screen usability sessions gated until the deployed revision and viewport are reviewed. Up to three inference-free sessions are owner-authorized; the opt-in [issue #13](https://github.com/stancsz/sift/issues/13) had no respondents at last check.
- **Public site:** GitHub Pages is live at <https://stancsz.github.io/sift/>. PR #7 added an offline Full / With Sift interaction that uses a captured result from the real compactor. The public evaluation/cost evidence refresh merged as PR #16 (`d4d9265`) and Pages deployment completed successfully. The GitHub repository homepage points to Pages.
- **Broader quality evidence:** a completed 344-question, three-repeat LongBench v2 run produced 2,063 valid receipts; one Full request returned HTTP 529 without a receipt and was not retried. On 343 fully receipt-matched task clusters, Full led Sift by 5.25 points in exact-choice task majorities (145/343 vs 127/343; task-cluster bootstrap 95% CI for Sift minus Full: −10.20 to −0.29 pp). Across all receipts, Sift used 59.66% fewer provider prompt tokens and had 58.72% lower cache-sensitive BYOK receipt cost. All tasks and labels were publicly exposed during development, so this is not blind validation or agent-task quality. The earlier 600-response study had a different sample and a smaller majority gap; do not pool them. A separate 950K-token Subroute probe measured Sifted usage on Astra and Gemini, while the full-context subscription calls were rejected; its no-Sift prices are rate-card equivalents, not measured costs. The user's $100 study cap covered prior settled spend and 13 conservatively reserved unknown attempts; the provider balance was unverified. AppWorld `test_challenge` remains parked until its output quarantine can be rehearsed without test access. See the [evaluation record](docs/evaluation.md) and [source review and protocol](docs/evals/agent-holdout-source-review-2026-10-18.md).
- **Adoption evidence:** the Advisor council recommended up to three inference-free first-run sessions with developers who already use long-context workflows. The [session protocol](docs/evals/first-run-usability-protocol-2026-10-18.md) is independently reviewed, but the homepage preview has not cleared the exact 1280×800 review gate. Recruitment is owner-authorized through the opt-in [issue #13](https://github.com/stancsz/sift/issues/13); no external participants have been contacted directly, and there were no respondents at last check. Record comprehension, setup time, blockers, relevance, and voluntary follow-through. Walkthrough completion is not adoption.
- **Compatibility:** automated checks cover non-streaming/SSE, incremental streaming, active tool-call/result turns, Bearer-key forwarding, upstream errors, and Ollama reasoning metadata. A local OpenAI Python SDK 2.54.0 → Sift → Ollama two-request tool round-trip passed on `qwen3.5:4b`, preserving `build-1842` while compacting both requests. This verifies that local loopback path, not other named clients or remote providers; check broader compatibility before a stable release.
- **Release:** `0.11.0.dev0` is installable from GitHub but is not a stable release or PyPI package. The standalone CLI smoke confirms the base install does not pull in LiteLLM; the base URL must still be an OpenAI Chat Completions-compatible endpoint, and `byte-estimate` cannot guarantee the provider's token count or context fit. A manual tag-based Trusted Publishing workflow and operator steps are prepared in [the release guide](docs/releasing.md); it verifies the selected stable tag, full suite, and offline comparison, builds and checks wheel/sdist, and smoke-tests both without LiteLLM before publishing. The public `sift-context` PyPI endpoint currently returns 404; owner-side pending-publisher configuration must be confirmed before first upload. Resolve the compatibility, evaluation, and adoption gates before a stable release.

## Evidence today

The [evaluation record](docs/evaluation.md) summarizes the completed 600-response and 344-question LongBench v2 studies, an incomplete 503-question matched run, a four-task field-pruning pilot, a 950K-token Subroute usage probe, and task-specific native-agent checks. All LongBench questions were exposed during development. The results are not blind validation, accepted-task quality, or proof of parity. The Subroute no-Sift prices are API-rate equivalents because both full-context subscription requests were rejected. Keep claims scoped to those datasets, denominators, and limitations.
