# Goal: LongBench v2 evaluation with OpenRouter MiniMax M3

## Objective

Complete a reproducible LongBench v2 follow-up using OpenRouter's MiniMax M3 route. Compare the unchanged default Sift selector with a research-only, option-aligned relation-matrix selector on six preselected tasks. Measure answer quality and efficiency together: exact-choice accuracy, provider prompt tokens, cache-inclusive upstream-reported cost, cache use, preprocessing time, model latency, and total pipeline time. Consider a 100-task follow-up only if the new controlled screen passes its predeclared gates and the freshly reconciled task-scoped budget permits it. The earlier 100-task full-context comparison is historical context, not a concurrent control.

## OpenRouter MiniMax plan

Use OpenRouter's `minimax/minimax-m3` endpoint, pin every request to provider `minimax`, and disable provider fallbacks. Record the endpoint metadata and the actual provider/model returned for each request. The current follow-up is a new, separately versioned v3 paired screen; it must remain separate from the stopped v1/v2 runs.

The v3 screen compares unchanged default Sift with a research-only, option-aligned complete-entity matrix on six preselected LongBench v2 tasks. It uses three matched repeat parameters per task and arm (36 requests total), a 32,768-token target, randomized order within each adjacent pair, one worker, and no retries. The candidate stays default-off. It must preserve the question, answer options, source paths, and every selected entity field. Save the exact request and hash before dispatch, then preserve every response—including invalid answers—plus route, token/cache/cost receipts, score, selector audit, preprocessing duration, model latency, and end-to-end pipeline time.

Keep operational safety separate from answer quality. Stop dispatch for confirmed route, usage, cost, prompt-limit, transport, or budget failures, counting already in-flight exposure. A billable HTTP 200 with truncated, malformed, or non-A–D output is an invalid answer: record it, score it incorrect, and continue the frozen run if operational checks still pass. Do not infer an answer from prose or retry. The expansion gate requires all 36 paired receipts, valid structured answers, correct MiniMax attribution and reconciled usage/cost, zero candidate fallbacks, at least one candidate-only task majority, and more exact-choice-correct candidate responses than default. A gate failure ends expansion consideration; a pass only permits an independent protocol and budget review.

Only after that review may a Stage 2 run be considered. The current proposal is a frozen 100-task development sample × three repeats (300 Sift requests), using the candidate only when its complete-entity audit passes and unchanged default Sift otherwise, with each fallback reason retained. This is a development sample, not the full LongBench v2 suite or a blind holdout. Reassess whether a full-suite evaluation is feasible after the v3 evidence and a fresh cost/runtime estimate; do not imply full-suite coverage from the 100-task stage.

For every stage, recheck live endpoint metadata, model/provider route, prices, request limits, source hashes, and cumulative task-scoped actual plus unsettled spend immediately before dispatch. The authorized aggregate ceiling is $20; include conservative remaining-call reserve and in-flight exposure, and do not launch if the projection exceeds it. Track OpenRouter's implicit prompt caching: report observed cache-inclusive upstream cost and cached tokens separately from a reconstructed uncached estimate. Measure answer quality and efficiency together—task and paired accuracy, provider prompt tokens, preprocessing, model latency, total pipeline time, and both observed and reconstructed cost. Historical full-context results are non-concurrent context, not a concurrent control. Publish only independently reviewed, task-scoped results; never turn a prompt-token or cost reduction into a quality claim.

## Cache and cost reporting

OpenRouter's MiniMax endpoint supports implicit prompt caching, and no verified cache-disable control is available. Do not claim a cache-cold run. Preserve `cached_tokens`, provider-reported `cost_details`, and upstream inference cost for every arm and repeat. Report actual cache-inclusive upstream cost by arm/repeat and overall, with cached-token counts and cache fractions beside it. First-repeat cost is not necessarily cold.

Also calculate a clearly labeled *reconstructed uncached estimate* from raw input/output token usage and the verified uncached rates. Validate its aggregation against the raw receipts and output-price components. Treat this as a counterfactual estimate, not observed billing. Because cache hits and shared prefixes can affect the two arms differently, show both the observed cache-inclusive savings and the reconstructed uncached estimate; do not collapse them into one marketing percentage. OpenRouter responses may show `cost: 0` and `is_byok: true`; call the upstream value provider-reported pass-through cost, not an invoice or independently verified charge.

Keep these measures separate:

- input-token reduction from provider-reported prompt usage;
- actual cache-inclusive upstream cost reduction;
- reconstructed uncached cost reduction;
- model latency and total wall-clock runtime, including preprocessing where measured.

For each savings percentage, state the formula, denominator, sample, repeat aggregation, date, and route. Include per-task and distribution data so a mean is not mistaken for a universal saving. Report full-context and Sift quality beside all efficiency numbers.
