# Goal: LongBench v2 evaluation with OpenRouter MiniMax M3

## Objective

Complete a reproducible LongBench v2 follow-up using OpenRouter's MiniMax M3 route. Compare the unchanged default Sift selector with a research-only, option-aligned relation-matrix selector on six preselected tasks. Measure answer quality and efficiency together: exact-choice accuracy, provider prompt tokens, cache-inclusive upstream-reported cost, cache use, preprocessing time, model latency, and total pipeline time. Consider a 100-task follow-up only if the new controlled screen passes its predeclared gates and the freshly reconciled task-scoped budget permits it. The earlier 100-task full-context comparison is historical context, not a concurrent control.

## OpenRouter MiniMax plan

Use OpenRouter's `minimax/minimax-m3` route, pinning requests to provider `minimax` and disabling provider fallbacks. The next experiment is a separately versioned v3 paired screen, not a continuation or pooling of either stopped v1/v2 screen: six preselected tasks × three matched repeat parameters × two arms (36 requests), with the option-aligned, complete-entity matrix candidate versus unchanged default Sift at a 32,768-token target. The matrix is default-off and must preserve all selected entity fields, question wording, answer options, and source paths. Accept only complete structured A–D answers; do not recover choices from prose, retry, or combine versions. Expansion consideration requires all 36 valid paired receipts, correct MiniMax route and reconciled usage/cost, zero candidate fallbacks, at least one candidate-only task majority, and strictly more exact-choice-correct candidate responses than default responses. A pass only permits a fresh budget and protocol review; it does not auto-launch Stage 2. If approved, Stage 2 uses a frozen 100-task sample × three repeats (300 Sift requests), selecting the matrix candidate only where its complete-entity audit passes and otherwise using unchanged default Sift with the fallback reason recorded. Preserve per-request payload/hash, route, tokens/cache/cost, scoring, preprocessing, model and pipeline timing, and selector audit. Recheck live endpoint metadata, source hashes, prices, request limits, and cumulative actual plus unsettled spend immediately before any dispatch. Report observed cache-inclusive upstream cost separately from reconstructed uncached estimates, and publish only independently reviewed conclusions supported by task-level evidence.

## Cache and cost reporting

OpenRouter's MiniMax endpoint supports implicit prompt caching, and no verified cache-disable control is available. Do not claim a cache-cold run. Preserve `cached_tokens`, provider-reported `cost_details`, and upstream inference cost for every arm and repeat. Report actual cache-inclusive upstream cost by arm/repeat and overall, with cached-token counts and cache fractions beside it. First-repeat cost is not necessarily cold.

Also calculate a clearly labeled *reconstructed uncached estimate* from raw input/output token usage and the verified uncached rates. Validate its aggregation against the raw receipts and output-price components. Treat this as a counterfactual estimate, not observed billing. Because cache hits and shared prefixes can affect the two arms differently, show both the observed cache-inclusive savings and the reconstructed uncached estimate; do not collapse them into one marketing percentage. OpenRouter responses may show `cost: 0` and `is_byok: true`; call the upstream value provider-reported pass-through cost, not an invoice or independently verified charge.

Keep these measures separate:

- input-token reduction from provider-reported prompt usage;
- actual cache-inclusive upstream cost reduction;
- reconstructed uncached cost reduction;
- model latency and total wall-clock runtime, including preprocessing where measured.

For each savings percentage, state the formula, denominator, sample, repeat aggregation, date, and route. Include per-task and distribution data so a mean is not mistaken for a universal saving. Report full-context and Sift quality beside all efficiency numbers.
