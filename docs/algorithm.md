# Algorithm and acceptance contract

Sift solves a bounded selection problem over **historical evidence**, not a summarization problem. The caller passes the same token-counting function used by its inference route. The output is accepted only when that counter reports `forwarded_tokens <= target`.

## Selection

1. Validate the raw estimate against `raw_limit`. Under target, return a copy unchanged.
2. For oversized requests, reject unsupported content and instruction messages after dialogue. Identify the latest real user turn; Anthropic user messages containing only tool results do not start a new turn.
3. Preserve the leading instruction prefix and all messages from the latest real user turn onward when they fit. If a long agent tool loop exceeds the target, preserve the original user request and the newest tool cycle, then retain up to three more cycles that fit. A task prompt or latest cycle that cannot fit causes an explicit capacity error.
4. In the normal case, walk backward over earlier real user turns. Keep at most four whole turns, subject to an 8,192-token cap and half of the remaining target. This prevents retaining a tool result without its initiating turn. In the long-loop case, partition older tool cycles into completed four-cycle groups. Rank each completed group against the unchanged original task, keep a bounded number of excerpts from each group, and evict oldest whole groups when the target is full. Extract an index of named failures from tool results, with at most 12 distinct, verbatim failure identifiers and 640 characters per result. The index omits surrounding error detail; other selected excerpts and exact recent cycles can retain that detail. Reserve the first historical failed-test index near the original task until that task ends when it fits; drop the reservation if it would crowd out the exact active work. This keeps a small baseline diagnostic even when its old four-cycle group is evicted. When the current group fits, reserve one third of the target for its exact messages and hold the historical prefix fixed until the next group boundary. If the exact group is too large, preserve the newest cycle and extract older cycles under the hard target.
5. Render older supported text/tool content as source text. Scan lines and bounded substrings without copying the remaining suffix of a long line. Count query-term frequency in the old history, then rank each center piece using query overlap weighted toward rarer terms, failure/decision signals, and recency. Follow up to four identifiers found in high-ranked center pieces to find distant related evidence. Reserve two directly ranked excerpts before joined excerpts. The identifier pass uses the unchanged original task for completed tool-cycle groups, so their excerpts remain fixed inside a cache boundary. Keep the immediately preceding and following pieces with each selected center so a failure line can carry its local diagnostic. Keep at most 512 candidates, with a bounded 65,536-hash deduplication window.
6. Quote candidates with source message indices and roles, order them chronologically, and place them in a user-role historical-data message. A binary search uses the caller's counter to select the largest fitting prefix of ranked candidates. There is no separate 96-excerpt ceiling; the target and candidate bound control the amount retained. Neighboring candidates can repeat source text, spending some budget on local coherence. No excerpt means an explicit capacity error.

The algorithm is deterministic for a fixed input and counter. It scans old text once for term frequencies, once for direct candidates, and once more when an identifier join is possible. Candidate storage and frequency counts are bounded by the candidate limit and current query terms rather than raw intake size. The caller's counter is invoked for the raw input, active/recent-turn checks, and at most a logarithmic number of final candidate checks. These counts can dominate CPU time if the caller's tokenizer is expensive.

The fixed historical prefix and exact current group let tool results append to the provider prompt between boundaries. Rollover, a large tool result, or older-group eviction can still change the prefix. The input target remains the caller's hard bound; Sift does not reserve or manage the provider's KV cache.

## Evidence and failure boundaries

The test corpus asks for facts buried in build logs, payment events, appointments, file errors, and research citations. A separate seeded test moves a unique fact through 100 middle positions. `benchmarks/compare.py` uses the same placements and reports 100/100 Sift retention against 0/100 for a head/tail excerpt with an 800-character allowance. The test deliberately favors query-aware middle retrieval, so it does not estimate general recall on real conversations. The tests assert exact retention, hard budget compliance, unchanged active messages, and no mutation. Five local Claude Code task traces were replayed privately at a forced 5K budget: original task and latest tool message were retained in 5/5, and a labeled initial test failure was retained in 5/5 later-query trials. This is a small compatibility and retrieval check, not a general recall estimate. The next acceptance step is a larger held-out corpus of real, consented agent traces with human-labeled must-retain spans.

The summary states that older content is untrusted historical data. This is a role and provenance convention, not a security boundary against prompt injection. Sift refuses media it cannot represent and refuses to erase oversized active work. It omits old Anthropic thinking blocks from extracted evidence, retaining current thinking blocks exactly. It does not repair provider errors, retry calls, or generate replacement answers.

## LiteLLM Responses selection adapter

The integration also accepts stateless text Responses histories. LiteLLM's installed transformer creates an inspection view for selection. Retained Responses items are then restored verbatim, including IDs, tool types, arguments, outputs, and plain reasoning summaries. Historical reasoning summaries are omitted from extracted evidence, as old Anthropic thinking is. Top-level instructions remain top-level and are counted once. Extracted older evidence becomes a quoted user-role message. Audit source indices refer to this grouped inspection view, not original Responses item offsets.

Only the first call in a pending parallel batch starts an eviction boundary. Reasoning between calls and interleaved outputs cannot split a batch. Incomplete or orphaned tool histories, stateful `previous_response_id`/`conversation` requests, encrypted reasoning, media, and unsupported built-in tools are rejected. This is a deliberate supported subset, not a general Responses implementation. LiteLLM continues to own the public protocol, streaming, provider conversion, and retries.

LiteLLM 1.103.0's route counter skips namespace wrappers, custom-tool descriptions, and some JSON Schema branches. Sift translates tool definitions with LiteLLM in a counting copy and charges the larger of the counter's formatted tool contribution and a serialized-schema token estimate. Missing array `items` are repaired only in that copy. Provider definitions and output limits stay exact. These private-counter workarounds should be removed when a supported LiteLLM version counts the complete shapes; they do not eliminate provider tokenizer/template drift.

For aggregate request logs, configure LiteLLM's log level to INFO. The `sift_request` record contains protocol, compaction status, raw/forwarded estimates, target, and requested output limit. It contains no request text. An unspecified output limit is logged as `-1`; Sift does not invent a limit.
